M07 adds `world_simulation_clocks`, `world_schedule_heads`, `scheduled_actions`, `simulation_batch_runs`, `simulation_worker_leases`, and `simulation_failures`, plus immutable `command_records.expected_aggregate_version`. Completed batch transitions require the matching open `AdvanceSimulationV1` command and a deferred commit-time proof that it became accepted. The simulation terminal guard likewise proves that the command's primary event uses the expected clock/schedule/failure aggregate type and `expected_aggregate_version + 1`, preventing a forged repository call from bypassing optimistic aggregate concurrency. Table and column grants keep allocation heads and leases behind security-definer functions while allowing only the runtime columns needed by clock, schedule, batch, and failure handlers.

Every anchored active world receives exactly one standalone system `InitializeWorldSimulationV1` command and `WorldSimulationInitializedV1` event after compiled/imported genesis. The fact advances event, ledger, runtime, outbox, history, graph checkpoint, and a separate `simulation_runtime` checkpoint by one revision; it creates tick 0 in `paused` mode and never advances time silently. Initialization also derives H0 exactly from the active `world_versions.seed`: SHA-256 first folds canonical JSON `{domain:"worldgraph.simulation.world-seed.v1",worldSeed}`, then folds canonical JSON `{domain:"worldgraph.simulation.outcome.initial.v1",outcomeSchemaVersion:1,prngAlgorithmVersion:"xorshift32-sha256-v1",processRegistryVersion:1,worldSeedHash}`. This matches the JavaScript `computeSimulationWorldSeedHashV1` plus `computeInitialSimulationOutcomeHashV1` boundary byte-for-byte. Existing worlds are upgraded in deterministic world-ID order. Fresh activation invokes the same idempotent initializer through a deferred owner-controlled `SECURITY DEFINER` trigger, so genesis and simulation initialization commit or roll back together. The separate deferred clock-write assertion is invoker-rights; the application role receives `EXECUTE` only on its required pure text-to-hash helper, while `PUBLIC` remains revoked. Reapplying the migration is a no-op at the deterministic command/event/ledger/outbox identities.

Clock initialization resolves the active compiled `simulation_configuration -> uses_primitive -> simulation.discrete_clock` relationship first. Compiled settings override defaults; the clock primitive supplies `tickDurationSeconds` and `maxCatchUpTicks` when settings omit them. Provenance is `compiled_configuration` only when every selected compiled value is valid; an invalid selection falls back atomically to the complete default set and records `m07_default`, rather than silently mixing values or overstating provenance. The sealed fallback is epoch `2000-01-01T00:00:00.000Z`, 86,400,000 world milliseconds per tick, 10,000 ms wall cadence, 64 ticks per batch, and 256 catch-up ticks. Bounds are enforced in PostgreSQL: tick duration 1..31,536,000,000 ms, cadence 100..86,400,000 ms, batch 1..256, catch-up 1..4096 with catch-up at least batch, and schedule priority -1000..1000.

Architecture decision: `worldgraph_simulation_projection_checksum` is intentionally separate from the M06 graph checksum and hashes semantic simulation state only. It includes clock configuration/current tick/mode/PRNG/cumulative outcome hash plus schedule head and each action's deterministic sequence, due tick, priority, type/schema, payload hash, process version, and status. It excludes row/state revisions, command/event/schedule UUIDs, timestamps/wall anchors, worker identities, fencing data, and batch/failure execution metadata. Consequently equivalent outcomes retain the same final checksum across worker identities and one-batch versus split-batch execution, while storage and API records keep the excluded operational evidence.

M06 does not invent worlds or history: it only anchors real active graph state found during an exact prior-head upgrade. M07 likewise creates no world or scheduled work; it initializes simulation only for real anchored active worlds. M08 and M09 add no value, title, resource, business, job, market, or tax data except through explicit compatible runtime initialization. Deterministic manifests/compiled worlds exist only in tests.
