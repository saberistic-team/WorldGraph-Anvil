# Testing strategy

Unit tests use Vitest with fixed clocks, deterministic identifier sequences, seeded XorShift32, and no public network. The inherited suites cover configuration, contracts/notifications, canonical JSON/hash vectors, redaction, identity/authority, health/security, primitive schema/dependency/retrieval/provider/queue behavior, and deterministic fixtures.

Manifest-focused unit tests cover:

- strict Manifest v1, generation envelope, API, notification, and queue-wake contracts;
- canonical JSON/content hashes, safe YAML golden projection/round trip, alias/tag/duplicate/prototype/non-JSON/depth/size rejection, and source locations;
- exact primitive identity/parameter/dependency/compatibility checks, unique/local references, graph connectivity, required mechanics, stable diagnostics/fixes, and structural diff bounds;
- deterministic seed/request/catalog/resolved hashes and fallback golden output;
- provider strict parsing, transient/repair limits, timeout, circuit/cost/token behavior, fallback selection, cancellation, queue validation, and notification redaction.

Real PostgreSQL integration tests cover fresh and exact prior-head upgrades, repeat migration, metadata compatibility, constraints/grants/triggers, prompt one-way/active-run retention, immutable revision/report/provenance/warning rows, frozen retrieval, monotonic numbering, generation leases/state/CAS/retry/cancel races, at-most-one output, UTC provider-budget reservation/settlement/release, repair caps, ledger reconciliation, stale edit/latest-only approval conflicts, creator-only approval, one current pointer, and rollback. API integration exercises real authentication/world authority, generation idempotency/cancellation and prompt-free wakes, cross-world/nonmember isolation, manual valid/invalid drafts, validation/diff, approval and direct SQL immutability. Worker integration covers claim/retrieval/fallback/publication, durable usage across retry, duplicate/lost wakes, cancellation and expired-lease recovery against PostgreSQL.

Playwright covers the staged `/worlds/[worldId]/manifest` journey at desktop and exact 320 by 720: durable polling/refresh, provider-disabled fallback, diagnostic/review/approval behavior, cancellation/recovery, prior identity/registry paths, keyboard/mobile behavior, XSS-safe rendering, and axe. Compose separately exercises production-built bootstrap, BFF/API/worker/PostgreSQL/Redis integration and dependency outage/recovery.

Compiler-focused unit and golden tests cover every pure stage; exact dependency ordering/missing/cycles; adapter allowlisting; primitive/manifest content hashes; integer-only PRNG vectors and unsafe-number rejection; stable logical keys; canonical sorting/hash; duplicate/dangling/cross-type edges; ordered diagnostics; observer/controller policy; artifact verification/tampering; size bounds; and absence of network, infrastructure, wall-clock, environment, or ambient random dependencies. The golden M04 fixture compiles in isolated processes under different timezone/locale settings and shuffled insertion order to byte-identical output. Seed/input/compiler changes alter identity, while an unchanged compiler/config version is pinned to the reviewed golden hash.

M05 PostgreSQL/worker tests cover fresh and exact-head migration/repeat no-op, application grants, lifecycle/run/claim/retry/cancel triggers, duplicate/concurrent starts, single claims, serialization/advisory-lock behavior, same-world composite foreign keys, relationship endpoint typing, logical-key uniqueness, controller/`account_controls` correspondence, one active version/runtime head, immutable successful graphs/artifacts, injected mid-seed rollback with no orphan rows, and durable sanitized failure. API tests cover creator/member/nonmember authority, stale/swapped manifest/hash/input, idempotency, request artifact injection, bounded query controls/cursors, cross-world scoping, and response contracts. Playwright covers compiler status/diagnostics/refresh and the authoritative overview/graph tables at desktop and exact 320-pixel mobile with keyboard and axe checks.

The offline CLI release check launches the built binary under plain Node in separate processes, compiles the same manifest/catalog/member/seed into two isolated output directories, byte-compares the compiler input, compiled artifact, and compiled world, verifies the content-addressed artifact in a third process, and checks the pinned counts/hashes. It writes no runtime table.

The sealed M05 final tree passed 47 unit files/270 tests, 12 real-service integration files/80 tests, 50 desktop/mobile Playwright cases, all 11 package typechecks and production builds, the migration/golden/standalone-CLI gates, and two clean/repeat Compose recovery drills. No skipped, planned, historical-only, or still-running test counts as evidence. Every later milestone must repeat and record repository format/lint/type/unit/build/migration checks, the full real-service integration suite, Playwright, clean/repeat Compose and recovery, dependency/license review, and independent blocker audit in proportion to its changes. A failed or unavailable prerequisite is recorded as not run, never as passed.

M06 adds strict command/result/actor/event/ledger/checkpoint/outbox/history contracts; registry/upcaster gaps; pure rename decisions/reducers; private-content rejection; canonical event/entry golden hashes; sequence/link/corruption checks; bounded export; visibility-before-pagination; and replay/checksum/repair-anchor determinism across locale/timezone processes. Command-bus tests pin stage order, authority, expected versions, durable rejection, exact idempotent replay, collisions, and shared-kernel use.

Real PostgreSQL M06 coverage applies a fresh and exact M05 upgrade, anchors an existing active world once, creates fresh compiled genesis in the activation transaction, compares SQL and JavaScript event/ledger/projection hashes, enforces application-role append-only and command write gates, checks atomic accepted/rejected/rollback behavior, races concurrent same-revision commands, projects outbox history with duplicate receipts and fenced leases, drives retry/dead-letter behavior, replays into durable shadow tables, compares checksums, and rejects unauthorized/destructive repair. Deliberate corruption must report the exact first divergent sequence without editing authority. Browser coverage exercises accepted rename, exact duplicate/uncertain lookup, stale conflict and refresh, history filtering/detail/badges, keyboard/mobile behavior, and axe.

M06 evidence is sealed only in `docs/milestones/06-command-event-ledger-state.md`; this strategy section describes required coverage and does not claim an unrun result.

M07 unit and golden coverage exercises checked integer world-time arithmetic, clock transitions, future-tick rejection, exact due ordering/tie-breaks, strict action/process/payload/event registries, keyed PRNG streams, fact/schedule budgets, deterministic notice execution, seed and outcome hashes, and simulation-ledger multi-event replay at one world revision. Static dependency tests keep the pure kernel free of infrastructure, network, AI, wall-time, and ambient-random imports.

Simulation replay tests additionally require exact aggregate-version and transition validation, full-stream hash/order/revision failure at the first bad event, event-recoverable failure resolution, payload-free divergence reporting, and equal final ID-free documents/checksums for one three-tick batch versus three one-tick batches. Real PostgreSQL operator coverage derives the replay seed from the genesis-bound immutable compiled artifact, proves JavaScript/PostgreSQL document and checksum parity, detects a deliberately changed live clock path, verifies the simulation checkpoint through `ledger verify`, rejects mismatched projection selection, and never emits notice payloads. Replay does not rebuild operational batch runs.

Real PostgreSQL and worker coverage applies fresh and exact M06 upgrades, repeat no-op initialization, valid compiled configuration/default provenance, application grants and protected transitions, semantic checkpoint equivalence across batch grouping, due discovery/order, lease acquire/renew/release/fencing races, duplicate/lost wake reconciliation, exact command replay, clock/pause/tick conflicts, schedule create/cancel/execute atomicity, bounded retry, terminal auto-pause/failure evidence, and Redis loss/recovery. API/security coverage binds world membership, creator/admin capabilities, expected tick/state/aggregate versions, query bounds, cross-world identifiers, server-only commands, and safe redaction.

Playwright covers the tick-3 notice demonstration, start/pause and bounded step behavior, exact-once completion after reload, read-only membership, loading, conflict/uncertain/degraded/auto-pause states, keyboard focus, 320-pixel mobile layout, and axe. Semantic golden runs vary worker IDs, wall timing, locale/timezone, input order, and batch grouping while requiring equal final simulation checksums. M07 evidence is sealed only in `docs/milestones/07-deterministic-clock-scheduler-state.md`; this section does not claim an unrun gate.

M08 unit/property coverage exercises canonical decimal/minor-unit round trips; noncanonical sign/zero/exponent/precision/leading-zero/overflow rejection; posting balance, supply/cap and nonnegative balance decisions; transfer/issuance/freeze/ownership/offer state machines; participant visibility before pagination; stable wallet lock ordering; and deterministic reconciliation documents/checksums. The pure economy package receives static dependency checks against database, network, AI, Redis, environment, wall-clock, and ambient-random capability.

Compiler compatibility tests keep the sealed compiler `1.0.0` artifact-1 fixture byte-identical while compiler `1.1.0` artifact 2 emits the exact hashed `EconomySeedPlanV1`. Native and legacy verification are explicit. Legacy adapter tests pin unique governance/controller selection, deterministic stable-key ordering, exact distribution/supply/title hash, ambiguity rejection, creator-confirmed adoption, and missing/incompatible-plan initialization failure without synthesized state.

Real PostgreSQL M08 coverage applies fresh and exact M07 upgrades, repeat no-op, contract/runtime/compiler/artifact metadata pairing, plan persistence/adoption/initialization, real application-role grants, composite same-world/currency keys, deferred posting sum, nonnegative balance/supply/cap, insert-only facts, one current owner/open offer, legal freeze/offer transitions, checkpoint/event/row parity, and current-tick expiry. Reconciliation rebuilds balance/supply/title from immutable facts, matches JavaScript/PostgreSQL canonical checksums, and detects deliberate fact/projection/head corruption without mutating authority.

Concurrency coverage launches 100 simultaneous debits against limited funds and verifies that accepted debits never exceed the original balance and each command/idempotency key has one effect. It also covers opposite-direction transfer lock ordering, duplicate delivery/reward, issuance-cap races, gift versus purchase, accept versus accept/cancel/expiry, and failure injection before and after every payment/title/offer persistence stage. Tests assert exact transaction, posting, event, ledger, projection, title, offer, and checkpoint totals after both success and rollback.

API/security tests cover forged controller/system/override/wallet/title identity, cross-world/currency references, stale versions, frozen currency/wallet, rate/feature controls, hostile amount/memo/metadata encodings, participant privacy, creator non-access, redacted telemetry, and uncertain-command lookup. Playwright exercises the two-user virtual-currency disclosure, exact transfer, concurrent insufficient-funds result, asset gift, atomic direct purchase, creator issuance warning, reconciliation, not-initialized/frozen/conflict/uncertain/error states, keyboard navigation, exact 320-pixel mobile layout, and axe. M08 evidence is sealed only in `docs/milestones/08-wallets-transfers-ownership-state.md`; this section does not claim an unrun gate.

M09 unit/property coverage exercises canonical fixed-point quantities at scales 0..12; bigint atom conversion; quantity × unit-price half-up conversion; floor/half-up basis-point assessment; inventory/reservation conservation; immutable recipe and tax-policy snapshots; business, employment, production, payroll, listing, and reservation state machines; partial-fill arithmetic; self-trade rejection; sorted target/wallet lock plans; periodic recurrence without catch-up; and deterministic expansion reconciliation documents/checksums. Static dependency tests keep pure commerce code free of database, network, Redis, AI, environment, wall-clock, locale, dynamic evaluation, and ambient-random capabilities.

Compiler compatibility tests must keep compiler `1.0.0`/artifact 1 and compiler `1.1.0`/artifact 2/plan 1 byte-identical while compiler `1.2.0`/artifact 3 emits exact `EconomySeedPlanV2` resource, recipe, inventory, business, facility, employment-offer template, policy, treasury, and schedule intent. Golden and separate-process CLI tests pin canonical bytes, hashes/counts, exact three-lane dispatch, shuffled-input/locale/timezone equality, plan provenance, business-affiliation validation, periodic payer-wallet validation, and rejection of silent upcast or synthesized commerce. They must not treat a compiler-authored offer as a worker-bound contract; contract creation and controlled-worker acceptance remain separate authenticated runtime effects.

Real PostgreSQL M09 coverage must apply fresh `0001`→`0012`, exact sealed-`0009` upgrade through the complete M09 chain, exact populated `0011`→`0012` upgrade, and repeat no-op; verify metadata/journal/checksum pairing, same-world keys, grants/write gates, quantity scale, reservation parity, immutable movement/recipe/work/trade/policy/assessment/reconciliation/repair facts, private command-payload/authority facts, payroll-policy selection evidence, durable rate scopes, outbox retry intents, legal lifecycle transitions, exact system-command event/cardinality, empty upgrade state until explicit plan-2 initialization, and empty repair/retry state until an owner-authorized operation is prepared. The sealed-`0009` fixture must include a genuinely active compiler-1.1/artifact-2/plan-1 world with initialized M08 runtime and economy state. Before/after assertions must prove that its artifact/plan identities, graph, controller/runtime heads, ledger/checkpoints, scheduler state, currency/wallet/journal, asset/title state, and canonical checksums are unchanged and that no M09 expansion or commerce rows were synthesized for it.

The upgraded-database demo is a second phase on that same migrated database: create a new world, compile and activate its compiler-1.2/artifact-3/plan-2 harbor artifact, explicitly initialize M08 economy and M09 commerce, and complete the full two-user company/facility/employment/production/market/tax/reconciliation journey. Passing only the legacy-world preservation test or only a clean/new-world demo is insufficient. The test must not recompile, upcast, regenerate, or initialize commerce in the existing active M08 world; that post-activation transition is reserved for M13. No current test constructs the required runtime-producible active-M08 preservation phase and then performs the native plan-2 demo against that same upgraded database, so this combined acceptance evidence remains missing and unrun.

Command coverage must prove that `CreateBusinessV1` binds an existing active organization wallet without changing supply or any balance, followed by a separately authorized and idempotent `TransferCurrencyV1` funding effect. Employment coverage must prove that seeded offers are templates, a manager creates the worker-specific offered contract, and only the controlled worker accepts it. Reservation coverage must prove that valid listing and production reservations terminalize through their owning aggregate commands and that no public, worker, or operator path exposes a targetless generic release/expiry mutation.

Settlement tests require inventory, balanced wallet postings, tax/fee/treasury, listing, trade, event, ledger, outbox, and all checkpoints to commit together or all roll back.

Concurrency coverage races at least 50 purchase attempts for one remaining unit, purchase versus cancel/expiry, two starts for limited production inputs, duplicate work/payroll delivery, schedule wake/restart, opposite-direction wallet involvement, and connection loss before/after each persistence boundary. The final-unit fixture now uses 50 independently authenticated buyers with distinct controlled entities and wallets and asserts 50 distinct command actors plus exactly one trade, inventory movement, financial transaction, and tax assessment with balanced postings. That strengthened scenario was added after dependency disruption and remains unrun; its result is still a release gate. The other invariants require nonnegative free inventory, one terminal target transition, one effect per command/schedule identity, and no partial state after injected failure.

API/security coverage includes cross-world/forged organization or controller identity, creator non-access to participant detail, stale world/state/expansion/tick/row versions, invalid scale/price/quantity, client-computed totals/tax/output/reward, self-trade, expired listing, policy mismatch, system actor/command forgery, changed idempotency reuse, cursor/filter isolation, and safe telemetry/realtime payloads. Reconciliation detects deliberate inventory/reservation/production/payroll/trade/tax/checkpoint divergence without mutation. Repair coverage must reject `RepairEconomicProjectionV1` at every public/API/browser/worker boundary and prove that the owner CLI enforces exact-head planning, 15-minute expiry, UUID-sorted deltas, distinct active preparer/approver identities, exact confirmations, approval-hash binding, append-only facts/event/override evidence, inventory-only guarded updates, an exact matched post-repair reconciliation/current checkpoint, idempotent receipt replay, and atomic rollback on any stale or malformed input.

Playwright covers the resources/business/production/market/treasury workspace, business/facility/employment/work/production/listing controls, itemized fixed-price purchase, no-real-money disclosure, second-user authority, conflict/uncertain/lag/empty/error states, keyboard/focus behavior, exact mobile layout, and axe. The default isolated suite uses deterministic route fixtures. `pnpm test:compose:browser` adds a non-mocked two-context leg to the real Compose journey: an authenticated desktop manager and independent 375-pixel mobile buyer preview and commit the three-unit purchase, the caller replays that exact UI-generated command identity, and a post-reconciliation browser phase visibly reviews manager/participant business and employment boundaries, paid work, completed production, the partial listing and immutable trade, the business wallet's balanced marketplace postings, treasury and tax totals, the matched checksum, and the filtered `WorldCommerceReconciledV1` history detail. Key pages run axe, mobile pages must not overflow, and navigation waits only for the document plus authoritative UI evidence rather than an open-ended network-idle state. This path is evidence only when it is actually executed against a clean and retained-data Compose stack.
