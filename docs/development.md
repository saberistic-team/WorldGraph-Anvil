# Development and configuration

## Toolchain

Use Node 22.23.2 from .nvmrc or .node-version and pnpm 11.9.0 from packageManager. The root lockfile is authoritative. Local Node 24 can execute the checks, but Node 22 is the release and CI runtime.

Production container builds use the named `api`, `worker`, `web`, and `migration` targets in the root Dockerfile. API and worker images copy only their bundled output and service-specific production dependency closure; web uses Next.js standalone output; migration uses the compiled database bootstrap plus reviewed Drizzle files. None of these runtime targets copies the root workspace dependency tree, workspace source/tests, or the root TypeScript compiler/`tsx`/Turbo/pnpm toolchain. PostgreSQL uses the upstream PostgreSQL 17/PostGIS 3.6 Alpine image and a checksum-pinned pgvector 0.8.1 source build. Because that upstream Alpine tag is currently amd64-only, local Compose defaults `POSTGRES_PLATFORM=linux/amd64`; set the variable only when an equivalent upstream architecture becomes available and has been scanned and extension-tested.

The workspace contains `apps/web`, `apps/api`, `apps/worker`, and domain/infrastructure packages including `catalog`, `contracts`, `manifests`, `compiler`, `ledger`, `simulation`, `simulation-command`, `economy`, `economy-command`, `governance`, `governance-command`, `config`, `db`, `observability`, and `test-utils`. Turborepo orders package builds. ESLint enforces that web cannot import database/server implementations, contracts cannot import frameworks/infrastructure, and the pure simulation/economy/governance packages cannot import wall-time, random, network, AI, or persistence adapters.

## Environment

`.env.example` documents every assembled M10 setting. API and worker validate configuration once during startup. `DATABASE_URL` is the least-privilege runtime connection; `MIGRATION_DATABASE_URL` is owner-only and used by explicit migration/catalog bootstrap; `OPERATIONS_DATABASE_URL` is owner-grade and must be supplied only to an audited ledger/projection/outbox maintenance process. `ALLOWED_ORIGINS` accepts a comma-separated explicit allowlist and rejects wildcard. `AUTH_PEPPER` is API-only and must contain at least 32 characters; the worker intentionally never receives it. `ENABLE_LOCAL_REGISTRATION` is for the closed-alpha/local path. Session idle/absolute TTLs are bounded and ordered. Outbox and simulation reconciliation, lease, retry, backoff, and batch settings are bounded and PostgreSQL remains their authority. `SIMULATION_CONTINUOUS_ENABLED=false` disables automatic advancement without deleting clock/schedule state or weakening manual command validation. Production rejects placeholder build revisions, pepper, and operational credentials.

Economy mutation controls are independent: `ECONOMY_TRANSFERS_ENABLED`, `ECONOMY_OFFERS_ENABLED`, and `ECONOMY_ISSUANCE_ENABLED` reject only their new commands, while `ECONOMY_DEBITS_FROZEN` is the broad emergency debit stop. Transfer/offer per-minute and issuance per-hour limits are bounded process-local abuse controls; database idempotency and serializable invariants remain correctness authority. `ECONOMY_OFFER_RECONCILIATION_INTERVAL_MS` and `ECONOMY_OFFER_RECONCILIATION_BATCH_SIZE` bound PostgreSQL discovery of tick-expired offers. That reconciliation remains active independently of Redis and `SIMULATION_CONTINUOUS_ENABLED`; no flag bypasses amount, posting, cap, controller, title, privacy, or command-ledger checks.

M09 scheduled commerce uses `COMMERCE_SCHEDULE_ENABLED` (default `true`), `COMMERCE_SCHEDULE_BATCH_SIZE` (default `25`, range 1..250), and `COMMERCE_SCHEDULE_RECONCILIATION_INTERVAL_MS` (default `1000`, range 100..60000). Disabling the bridge stops new production-completion, payroll, listing-expiry, and periodic-tax system-command submissions without deleting their PostgreSQL schedules or targets. Redis remains wake-only; PostgreSQL discovery plus fixed schedule-derived idempotency provides recovery. `ECONOMY_JOBS_ENABLED`, `ECONOMY_PRODUCTION_ENABLED`, `ECONOMY_LISTINGS_ENABLED`, and `ECONOMY_PURCHASES_ENABLED` independently refuse those new public mutations; their work, production, listing, and purchase rate limits are bounded from 1..1000 per minute. Those four limits are evaluated inside the serialized command transaction against durable one-minute actor/world/type/target-scope history; changing a process or idempotency key does not erase the target evidence. `ECONOMY_DISABLED_TAX_POLICY_IDS` defaults empty and accepts at most 64 unique comma-separated UUIDs; API and worker must receive the same value and restart after it changes. A disabled policy is excluded from new job and market policy selection, including purchase preview, allowing the next eligible active policy or no assessment; already-snapshotted payroll obligations remain immutable. A disabled periodic policy is neither discovered nor directly assessed, and its completed durable schedule is left untouched. Re-enabling it lets PostgreSQL recovery assess it at the authoritative current tick and resume the existing skip-missed recurrence rule. No configuration bypasses fixed-point validation, inventory reservation, balanced M08 postings, policy assessment, authority, tick, ledger, or checkpoint constraints.

M10 governance scheduling similarly uses `GOVERNANCE_SCHEDULE_ENABLED`, a bounded batch size, and a bounded PostgreSQL reconciliation interval. When enabled, the worker requires a separate `GOVERNANCE_TALLY_DATABASE_URL` for the restricted aggregate-only tally role and fails readiness when that boundary is unavailable or over-privileged. Contest creation, voting, enactment, and explicit overrides have independent pause flags; disabling a class does not delete durable contests or schedules and cannot grant authority. Proposal, sponsor, vote, and nomination limits are bounded abuse controls backed by authoritative command/idempotency rules. `GOVERNANCE_TWO_PERSON_CONTROL_ENABLED` requires a fresh, distinct, command-bound approval for override and repair, while `GOVERNANCE_STEP_UP_TTL_SECONDS` bounds the password-reauthentication proof to 30–900 seconds. No flag, approval, browser capability, or Redis message can bypass the compiled charter, current tick, target versions, immutable tally, treasury checks, ledger, or explicit override classification.

Primitive semantic indexing is disabled by default. `PRIMITIVE_SEMANTIC_PROFILE` accepts only `disabled` or `local_hash`; the latter is the built-in deterministic, local-only 1,536-dimension feature hash and makes no network call, reads no secret, and records zero cost. `PRIMITIVE_SEMANTIC_CONTRIBUTION_ENABLED` independently controls whether matching current vectors contribute to retrieval. Enabling contribution while the profile is disabled fails startup. `PRIMITIVE_EMBEDDING_COST_BUDGET_MICROUNITS` must be explicitly zero because no paid profile is supported. Provider timeout, maximum jobs per reconciliation, and reconciliation interval are bounded; the job/interval pair is also the maximum indexing rate even under duplicate queue wakes. API and worker must receive the same profile settings.

OTEL_EXPORTER_OTLP_ENDPOINT is an OTLP/HTTP base URL. When set, API and worker export traces to v1/traces and metrics to v1/metrics and flush during graceful shutdown. An empty value is an explicit local no-export mode, not a fake success state.

ENABLE_OPERATIONAL_SMOKE defaults false. When true, OPERATIONS_TOKEN must be at least 32 characters. The token is entered at the operations UI or sent as a Bearer credential; it is never exposed by system-info.

## Common commands

- pnpm dev runs source-mode web/API/worker; PostgreSQL and Redis must already be reachable.
- pnpm bootstrap builds and starts the complete Compose stack; its one-shot prerequisite migrates and idempotently imports the 20 reviewed primitives.
- pnpm db:migrate applies committed migrations using the owner URL. Runtime startup never migrates.
- pnpm db:seed:primitives imports or integrity-verifies the reviewed catalog using `DATABASE_URL`; use an owner-equivalent URL for release bootstrap.
- pnpm db:check checks file/journal/checksum drift without contacting a database.
- pnpm outbox retry runs the owner-only dead-message recovery workflow; it requires `OPERATIONS_DATABASE_URL`, an active platform administrator, a new reviewed retry UUID, and the exact procedure in `operations.md`. It is not a normal developer or worker retry command.
- pnpm check runs the fast required gate; pnpm verify adds integration and browser suites.
- pnpm test:compose runs the real multi-user API/BFF/worker/database recovery journey, including three-account public governance, tax/project enactment, election certification, and the complete commerce path. `pnpm test:compose:browser` adds live headless creator/observer governance review and an explicit password-reauthenticated override, plus independent desktop-manager and mobile-buyer commerce sessions. Install Chromium first with `pnpm exec playwright install chromium`; neither command substitutes for clean and retained-data runs required by milestone evidence.
- pnpm reset:local removes the local volume. This is destructive to local-only data.

Do not add domain state to Redis, import packages/db from web, make an external model call from deterministic tests, or edit an applied migration. Every later milestone must update the milestone state record convention described in docs/milestones/README.md.

The browser calls only the allowlisted same-origin `/api/v1/*` BFF. It forwards Cookie, Origin, CSRF, idempotency, content type, and all Set-Cookie headers, never Authorization. A 204 upstream response must remain bodyless. Invitation tokens belong in URL fragments and transient component memory only.
