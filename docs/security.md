# Security baseline

- Runtime configuration is validated once at startup. Explicit origins replace wildcard CORS. Request/body/time limits, content-type validation, Helmet headers, and route rate limits are server-side.
- Only `.env.example` is committed. Docker excludes environment files other than that example, key material, logs, reports, source-control metadata, and local dependencies. Runtime images are non-root and contain bounded runtime/migration material rather than the repository wholesale.
- Logs recursively redact authorization, cookies, credentials, passwords, secrets, session values, tokens, API keys, prompts, manifests, provider payloads, and common credential-like free text. Error stacks and raw dependency/provider errors are omitted from public responses.
- PostgreSQL owner credentials are reserved for migration/catalog bootstrap and reviewed repair or outbox recovery. The application role is non-superuser/non-creator and receives explicit column/table/function grants. Database triggers/functions protect append-only audit/events/ledger/history, guarded graph projections, immutable published primitives, manifest content/provenance/reports/warnings, generation claims/state/provider accounting, active-run prompt retention, latest-only approval, and approved-pointer consistency. `OPERATIONS_DATABASE_URL` is never an API/web/ordinary-worker secret.
- Redis is non-authoritative. Queue delivery is at least once and processors are idempotent. Primitive index intent and manifest generation runs live in PostgreSQL; loss, duplication, or recreation of Redis cannot create or erase authoritative domain state.
- Dependency versions and permitted native install scripts are pinned. CI runs high-severity audit plus dependency/license review. GPL-3.0 and AGPL-3.0 additions fail review. The M05 production inventory has no high/critical advisory; it retains one moderate PostCSS advisory through Next. Sharp's optional prebuilt dynamically linked libvips runtime is LGPL-3.0-or-later and requires preserved notices/dynamic-link compliance, while `caniuse-lite` data is CC-BY-4.0.
- The current unified runtime image ships the workspace root dependency tree, including development tooling needed by the TypeScript bootstrap path. CI audits the complete lockfile, but release inventory must distinguish production dependencies from the larger physically present image surface until bootstrap is compiled and service images use pruned dependency trees.

## Identity and world authority

Passwords use vetted Argon2id plus a server pepper. Session, CSRF, invitation, network-prefix, and user-agent values use domain-separated hashes; raw credentials and request bodies stay out of logs/audit. Unsafe session requests require exact configured Origin plus session-bound double-submit CSRF. Cookies are HttpOnly where appropriate, SameSite Lax, secure in production, and forwarded only through the narrow same-origin BFF.

Membership is current world authority; immutable creator provenance is not. Repository reads are world-scoped and database constraints prevent zero/multiple creators. Platform administration never fabricates a world role. Manifest reads require active membership, creator/administrator roles may generate/edit/validate, and only the active creator may approve. Cross-world IDs receive non-enumerating not-found responses. Idempotency identity includes actor/action/resource/request hash, and stale hashes/row versions fail closed.

Audit metadata is allowlisted and recursively rejects secret-like keys. Creator overrides remain explicit, reasoned, linked, immutable, and metered, but no override can bypass Manifest v1 validation or creator-only approval. Active-world commands derive actor, correlation, causation, authority rule, and override on the server; a client cannot select system/AI/platform actors or submit an override. Idempotency is bound to actor, world, type, and canonical request hash, while design/state/aggregate versions reject stale replay.

Domain events and ledger entries are insert-only and per-world ordered. The application role cannot update allocation heads; security-definer insert triggers allocate exact contiguous event/aggregate/ledger positions. Opening a command records an owner-written pre-command revision/sequence/checksum snapshot, and a deferred terminal constraint rejects orphan events, missing outbox links, head jumps, nonterminal opened commands, or projection/event changes disguised as rejection. SHA-256 canonical hash chaining is tamper evidence, not protection against a fully privileged database administrator. Narrow grants/triggers, encrypted backups/PITR, scheduled external verification/checkpoints, restricted exports, and incident response remain required. Replay runs against isolated shadow tables and never changes authority. Projection repair requires owner credentials, explicit confirmation, a successful unchanged-head replay, a reason, and two distinct active platform-administrator approvals. Economy repair instead binds an exact private compensating plan to the unchanged reconciled head and requires one active creator plus one distinct active platform administrator; the approved administrator executes it with owner credentials. Both paths append evidence and never rewrite an event.

Simulation is server-authoritative and fail-closed. Manual actions traverse the same session, Origin/CSRF, authority, expected-version, idempotency, event, ledger, and projection controls. Browsers cannot select a system actor, initialize or auto-pause a clock, submit lease/fencing data, or schedule hidden handler types. The worker has one fixed simulation principal and must prove the exact PostgreSQL lease owner/fencing epoch inside the same serializable command transaction; Redis/BullMQ values never confer authority.

Simulation actions and returned facts use strict code-owned allowlists and bounded schemas. Current/past schedules, excessive tick/catch-up/fact/schedule/text/payload values, unknown action/process/schema versions, cross-world IDs, illegal status transitions, and forged aggregate versions are rejected. The pure process package has no network, AI/provider, database, Redis, filesystem, environment, wall-clock, locale, dynamic evaluation/import, or ambient-random capability. Notice text is rendered as text and classified before history pagination; logs, traces, metrics, queues, failure context, and public status omit notice text/payloads. Deterministic process failure rolls back and ultimately auto-pauses instead of skipping an action.

Economy and title are server-authoritative and closed-loop. Canonical decimal strings are converted directly to checked bigint minor units; floating point, exponent input, external address, cash-out, exchange, crypto, provider, AI, and client balance/title decisions do not exist. Every handler reloads active controller authority and same-world/currency references under a serializable transaction. Sorted locks, expected versions, idempotency, immutable accounting/title facts, nonnegative balance/supply/cap checks, deferred posting balance, and one current-owner projection prevent double spend, duplicate reward, and partial purchase. Currency and wallet status can change only through registered freeze/unfreeze commands. Creator issuance is a distinct reasoned, capped, rate-limited override and never a direct balance edit.

Assets contain no owner field. Metadata is bounded, schema-versioned, inert data rendered as text; external URLs, payment identifiers, executable fields, and unbounded arbitrary objects are rejected. Offer expiry uses the persisted simulation tick and the same command/event gate as interactive terminal transitions. Redis, wall time, and feature flags confer no financial or title authority.

Financial history adds `participant` visibility. Only active controllers of entities represented in a transaction may read private wallet/posting detail; active creator status alone is insufficient. Visibility is resolved before cursor pagination. Private memo, posting payload, amount, controller/session/IP data, and wallet/asset identifiers are excluded from logs, metrics, queue messages, failure context, and public history. Reconciliation exports bounded counts/hashes, not private journals. Repair is append-only or restore/PITR and requires reviewed dual operational authority; direct update/delete of facts or projections is forbidden.

Productive commerce preserves that boundary. Resource quantities are exact fixed-scale values and money stays checked minor units; client floating-point values, totals, tax, fee, wage, output, reward, tick, treasury selection, and ownership are never authority. Inventory availability is derived after locks from quantity minus active reservations. Immutable movements and unique source ordinals, exact recipe/policy snapshots, one terminal lifecycle transition, sorted locks, and schedule-derived idempotency prevent double consumption, duplicate payroll, overselling, and partial settlement.

Rate-limited commerce commands carry a mandatory immutable SHA-256 target-scope hash in the durable command record: contract for work, facility for production, seller inventory for listing creation, and listing for purchase. The bounded policy is evaluated inside the serialized command transaction against the preceding one-minute world/actor/type/scope history. Process restart, Redis loss, or changing an idempotency key therefore cannot erase target-specific velocity evidence. Raw target identities are not telemetry labels.

Economy abuse telemetry is deliberately low-cardinality and non-authoritative. The only emitted label values are `self_trade_attempt` and `rapid_circular_transfer`; participant, wallet, listing, world, transaction, amount, payload, and policy identities are excluded. A same-entity purchase is still rejected by command authority, while common control of distinct buyer/seller entities and a recent transfer cycle emit a signal without changing the transaction decision.

Business authority is current organization control or current control of a player character whose active state declares the backing organization. Creator provenance does not grant business management or access to another participant's inventory, contract, work, payroll, trade, or wallet detail. Those records are authorized before cursor pagination. Public treasury reads are bounded aggregates; schedule payloads and `CommerceNotificationV1` carry target/change identifiers and revision/cursor only, never amounts, wages, counterparties, policy predicates, or posting details.

Production completion, payroll settlement, listing expiry, and periodic tax are fixed system-only command types. A browser cannot choose the system actor, schedule causation, idempotency key, output, payroll, or assessment. The worker derives them from an already-completed PostgreSQL M07 action and rechecks target state inside the serializable command transaction. Redis delivery and worker memory are never authority. Periodic recurrence skips missed intervals instead of creating an unbounded catch-up charge.

Fixed-price purchase rejects self-trade and recomputes the complete settlement. Inventory movement, reservation/listing state, balanced zero-supply buyer/seller/treasury postings, immutable trade/assessment, event, ledger, outbox, and checkpoints commit together or not at all. Treasury is an ordinary M08 wallet; no second balance field exists. Tax policies are immutable compiler-provenance facts, not mutable client or AI decisions. Compiler validation and a PostgreSQL exclusion constraint reject overlapping active half-open windows for the same world, currency, tax type, and normalized applicability; periodic cadence cannot disguise a duplicate payer scope.

M09 reconciliation is read-only. Migration `0012` removes mutable command payloads and current projections as sufficient rebuild authority by freezing bounded payload and authority documents for the five history-sensitive commerce commands. Each access-private fact carries separate payload/authority hashes plus the exact publication event sequence, expansion-head checksum, projection-checkpoint checksum, and a canonical evidence checksum. Payroll policy selection is likewise frozen with its work/payroll, policy, amount, command/event, revision, and checksum evidence. The application role cannot read these fact tables; it can only use the narrow command-path recording functions and insert the payroll selection fact required by the write gate.

Reconciliation schema 2 compares exact business, facility, contract, listing/trade, payroll, assessment, inventory, reservation-lifecycle, recipe-version, tax-policy, checkpoint, and production documents. Production evidence binds the initial snapshot/transition; completed aggregate-version-2 consumption event and aggregate-version-3 output event; failed aggregate-version-2 event; exact reservation terminals; and resource-movement envelopes. A corrupted event ordinal/type/version, movement, recipe version, policy, payload authority, or checkpoint therefore produces a mismatch rather than becoming its own rebuild authority.

The separate private `RepairEconomicProjectionV1` workflow has no public registry, HTTP, browser, or ordinary worker authority. It can correct only inventory quantity/reserved-quantity projections to exact immutable-fact rebuilds after a 15-minute unchanged-head plan prepared by one active platform administrator, approval by a distinct active platform administrator, and execution by that approver through an owner-authorized session. Execution appends repair facts, a private event, approval override and repair-anchor ledger evidence, and a matched reconciliation/current checkpoint; it never rewrites or deletes immutable authority. Other mismatch classes require mutation freeze and whole-database restore/PITR or another separately reviewed forward design. Direct unaudited edits to inventory, reservations, production, payroll, listings, trades, policies, assessments, treasury, events, ledger, or checkpoints are prohibited.

All currency, wages, prices, fees, taxes, and treasury values are simulation-only with no cash value or cash-out. No fiat purchase, redemption promise, exchange, crypto address, external payment token, debt, interest, escrow, auction, order book, or runtime AI economic decision is accepted or emitted. Product UI, support material, logs, analytics, and exports must preserve that disclosure.

History templates and outbox payloads are allowlisted, versioned, and minimal. Visibility (`public`, `member`, `creator`, `participant`, `operator`) is filtered before pagination so hidden rows do not leak through counts or cursor gaps. Public history/status APIs never return raw command/event payloads, request hashes, secret material, or arbitrary JSON rendering. Privileged operator commands require both database-owner membership and an explicit active platform-administrator identity. Operator exports create a new mode-`0600` file, refuse overwrite, append redacted authorization/completion audit rows, and follow the deployment evidence-retention policy.

A dead outbox message can be requeued only through `worldgraph_retry_dead_outbox_message`: an owner-only `SECURITY DEFINER` function with a fixed search path and `PUBLIC`/application execution revoked. The caller must name an active platform administrator, supply the exact confirmation and a bounded 20–1000-code-point incident reason, and use a distinct retry UUID. The function holds the world advisory lock, appends an audit row and access-private `outbox_retry_intents` fact, and exposes a one-transaction secret only to the protected `dead`→`pending` transition. The application role has no privileges on the intent table or protection function. Message/event/type/schema/payload identity and attempt count are preserved. Direct terminal-row mutation and changed inputs under the same retry UUID fail closed; if that message later becomes dead again, the old UUID returns its original intent/current dead status without requeueing, and the operator CLI requires a new reviewed retry identity.

The `0012` journal/checksum check passed at index 11 with SHA-256 `44de5f5ee34430d32b5b6866f4469dc7e843293f378490b935ca7f80295a4709`. Fresh and exact `0011`→`0012` migration tests define the role, grant, baseline-evidence, rollback, and outbox-retry assertions, but could not run against live PostgreSQL in this environment. Milestone 09 remains implemented but not sealed.

## Untrusted primitive, prompt, YAML, and model data

Primitive definitions, documentation, creator prompts, YAML, model output, validation fixes, Markdown, and provenance assertions are untrusted inert data. Security does not depend on regex-only prompt-injection detection.

- Manifest/primitive schemas are strict, local-reference-only, bounded, and reject unknown keys, remote/dynamic references, arbitrary URLs, executable/template/SQL-like fields, control/lone-surrogate content, prototype keys, non-allowlisted behavior names, invalid identifiers, unpinned primitive versions, and illegal references.
- YAML uses the JSON schema mode and rejects aliases/anchors, merge keys, duplicate keys, custom/executable tags, multiple documents, non-JSON values, excessive depth/nodes/properties/lines, prototype keys, controls, and documents over 131,072 bytes. Canonical JSON is authoritative.
- The generation provider port is schema-only and receives no database, command, tool, URL-fetch, filesystem, network, compiler, or runtime capability from WorldGraph. Inputs label and delimit untrusted prompt/primitive text. Outputs are locally parsed and validated; at most two repair attempts receive structured diagnostics only.
- Provider transient retries, timeout, output tokens, daily cost, independent per-world/per-requester concurrency, circuit breaking, cancellation, and feature flags are enforced outside model output. World counting is serialized by its locked row; cross-world requester counting uses a transaction advisory lock. Per-call cost/tokens use claim-bound append-only reservations under a global UTC-date database lock, and provider-mode success must reconcile a settled ledger. Production supports only `disabled-v1`, for which provider reservation is database-rejected; the deterministic fallback uses exact catalog pins and passes the same validator.
- Generation creates proposal records only. Human creator approval revalidates the immutable content and exact pins inside a locked transaction. Approval cannot compile, seed, activate, execute governance/economy, or mutate runtime state.

Prompt text is access-restricted PostgreSQL data. There is no prompt read API. The configured 1–365 day retention defaults to 30; bounded cleanup can only null text after `retention_until`, and triggers reject early or active-run erasure, restoration, redacted-prompt generation, identity/hash edits, or deletion. Normalized hashes, exact retrieval/provenance, approved content, and audit identity remain for integrity. Managed environments must provide reviewed encryption-at-rest and key controls.

No raw prompt, manifest, provider payload, chain of thought, provider error text, cookie/token, or user/world ID as a metric label is allowed in telemetry. UI rendering is escaped/text-first; downloaded canonical JSON/YAML is data, and diff/diagnostic content is not interpreted as HTML.

Report a suspected secret or sensitive prompt exposure immediately, disable the provider/generation path if relevant, rotate secrets outside Git, preserve sanitized audit evidence, and inspect image/history/log/trace exports. Do not commit replacement secrets. High or critical known vulnerabilities block milestone acceptance unless the owner records an explicit risk acceptance.
