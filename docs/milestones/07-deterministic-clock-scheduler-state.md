## Outcome and implementation summary

Milestone 07 adds the first authoritative simulation slice. Every initialized active world owns one persistent PostgreSQL clock and schedule head. The clock begins at tick `0` in `paused` mode, and world time is derived from a normalized epoch plus checked integer tick multiplication. Manual and automatic advancement use the M06 command/event/ledger boundary. PostgreSQL clock, schedule, event, ledger, checkpoint, batch, lease, and failure state determine the result; wall time and Redis/BullMQ only propose bounded work.

The release adds:

- `packages/contracts`: strict v1 clock, schedule, process/context/result, batch, failure, queue, projection, outcome and PRNG contracts; public and system simulation commands; 12 simulation event variants; query transports; compatibility schema 7; process registry 1; and algorithm `xorshift32-sha256-v1`.
- `packages/simulation`: checked tick/time arithmetic, clock state transitions, future-only scheduling, exact due ordering, fact/schedule budgets, deterministic keyed PRNG streams, semantic outcome folds, and a code-owned pure registry containing only `EmitWorldNoticeV1@1.0.0`. Static architecture checks exclude persistence, network, Redis, AI, filesystem, locale, wall-clock, environment and ambient-random capabilities.
- `packages/simulation-command`: deterministic advance planning and a narrow PostgreSQL system-command adapter. It executes one bounded range through the same ledger/projection semantics as public commands while binding the fixed system actor and live lease fencing proof.
- `packages/db`: forward migration `0008_deterministic_clock_scheduler`, Drizzle parity, six simulation tables, immutable expected aggregate versions, simulation projection document/checksum, schedule allocation and legal-transition guards, lease acquisition/renewal/release fencing, batch/failure proofs, corruption-freezing command-gate checks, deterministic initialization, and restrictive grants.

## Clock, schedule, process, and outcome invariants

- World time is `epochUnixMilliseconds + tick × worldMillisecondsPerTick`, calculated with checked integers. Tick and PostgreSQL values are nonnegative signed 64-bit integers; configuration proves tick `1` is renderable and every advance proves the target instant is a valid canonical UTC timestamp. Numeric or calendar-range exhaustion rejects or auto-pauses with `SIMULATION_INTEGER_OVERFLOW`; it never wraps, clamps, or silently advances.
- A public reconfiguration is allowed only while paused at tick `0`. Start creates a fresh wall anchor, pause clears it, and paused/error clocks never infer elapsed ticks. Continuous elapsed wall time is only a wake proposal; accepted commands record exact `fromTick`, `toTick` and `tickCount`.
- New schedules must be strictly after the authoritative current tick. A schedule proposed inside an advance must remain strictly after that command's final tick, so it cannot be created and consumed in the same replay group. Due work is read in exact `(due_tick ASC, priority ASC, schedule_sequence ASC, id ASC)` order. Schedule sequence allocation is transactional and world-local. An action has one immutable identity. M07 permits one legal `scheduled → completed|cancelled` terminal transition; the schema reserves `failed`, but its trigger rejects that transition until a future versioned command defines it. Execution failure therefore leaves the action scheduled and records separate batch/failure/auto-pause evidence.
- One accepted advance changes the world revision once, regardless of event count. It emits one `SimulationAdvancedV1` plus, per executed notice, `ScheduledActionExecutedV1` and `WorldNoticeEmittedV1`. The command fact budget is 64, so one advance executes at most 31 notices. Any invalid handler result, budget excess, conflict or fencing loss rolls back the full range.
- `EmitWorldNoticeV1@1.0.0` receives an immutable validated context, derived integer time, current semantic checksum, and a deterministic substream keyed by process identity, tick and stable schedule key. It returns typed proposed facts/schedules only. Unknown action/process/schema/algorithm versions fail closed; manifests cannot select code and there is no dynamic import/eval.
- The cumulative outcome fold covers the prior semantic state, immutable compiled world seed hash, PRNG/process versions, exact tick, ordered due-action semantics, typed returned fact bytes and proposed schedules. It excludes generated UUIDs, command/event/ledger IDs, timestamps, state/row revisions, worker/lease identity, attempts and batch grouping.
- Graph and simulation integrity are separate. The M06 graph checksum retains its state-revision-aware semantics. The simulation checkpoint hashes the ID-free clock configuration/current semantic state, PRNG/outcome identity, schedule head, and ordered action sequence/due/priority/type/schema/payload-hash/process-version/status. Different worker IDs, wakes and one-batch versus split-batch execution may produce different operational rows but must converge to the same outcome hash and simulation checksum.
- Once any simulation state exists, opening any ordinary command for that world requires a current schema-1 `simulation_runtime` checkpoint at the runtime event head, exact live semantic checksum parity, and a gap-free schedule projection whose head equals both action count and maximum sequence plus one. Divergence freezes writers. A transaction-local command setting is not authority: the corresponding database command must still be `received`, have a fresh owner-opened gate timestamp in the current transaction, and contain the M06 opening state/event/ledger snapshot. Checkpoint insertion/update itself requires that exact open command, a matching final event and a freshly recomputed checksum, preventing an application caller from certifying corrupt live state by setting session variables or rewriting only the checkpoint.
- The simulation command/event/aggregate namespace is a closed matrix. Deferred database proofs bind scheduled-action creation to its accepted command, actor and literal `ScheduledActionCreatedV1` payload/hash; completion/cancellation and each adjacent world notice to their exact rows and facts; clock insert/transitions to exact command payload hashes, event payloads, modes, ticks, wall anchors and timestamps; a completed batch to its accepted `SimulationAdvancedV1` range/outcome; and failed batch/failure/resolution evidence bidirectionally. A forged row or broadly plausible event cannot become authority merely because it reuses a command ID or reserved type.
- Every fact's `event_ordinal` must equal its exact position after that command's owner-opened world event sequence, with a contiguous `0..n-1` group of at most 64 facts. Reserved command, event and metadata JSON reject non-canonical numeric spellings before row/fact parity is certified.

Database bounds are world duration 1–31,536,000,000 ms, wall cadence 100–86,400,000 ms, batch 1–256 ticks, catch-up 1–4096 ticks with catch-up at least batch, priority -1000–1000, notice text 1–500 characters, schedule payload at most 4096 bytes and failure context at most 16,384 bytes. Payload hashes are recomputed from canonical JSON. The clock outcome hash, schedule sequence, status transitions, lease epochs, batch completion, failure resolution, aggregate version and final checkpoint are guarded by constraints, security-definer functions, triggers and deferred terminal assertions.

Every already anchored active world is initialized in deterministic world-ID order by one standalone `InitializeWorldSimulationV1` system command and `WorldSimulationInitializedV1` event after its honest M06 genesis. The command creates tick `0`/`paused`, schedule head `1`, simulation-clock aggregate version `1`, ledger/history/outbox evidence, and current graph plus `simulation_runtime` checkpoints without creating a world, advancing time or scheduling work. Reapplying the exact migration is a no-op at deterministic command/event/ledger/outbox identities. Missing, partial or divergent initialization fails closed for forward repair.

Clock initialization selects a complete valid compiled discrete-clock configuration or the complete default set; it never mixes sources or overstates provenance. The default is epoch `2000-01-01T00:00:00.000Z`, 86,400,000 world ms/tick, 10,000 ms wall cadence, 64 batch ticks and 256 catch-up ticks with provenance `m07_default`. A complete valid selection records `compiled_configuration`. An invalid selection, including a tick-1 instant outside the supported canonical calendar, uses the complete default set. Fresh activation invokes the same idempotent initializer through the deferred owner-controlled activation transaction, so graph genesis and simulation state commit or roll back together.

The initial outcome hash is derived byte-for-byte in TypeScript and PostgreSQL from the immutable active `world_versions.seed`: first hash canonical `{domain:"worldgraph.simulation.world-seed.v1",worldSeed}`, then fold canonical `{domain:"worldgraph.simulation.outcome.initial.v1",outcomeSchemaVersion:1,prngAlgorithmVersion:"xorshift32-sha256-v1",processRegistryVersion:1,worldSeedHash}`. The migration creates no production seed beyond the retained public compatibility metadata and reviewed 16-item primitive catalog.

## Worker, failure, replay, and recovery state

The worker discovers due running clocks in deterministic PostgreSQL order. It acquires one expiring world lease, reloads clock/runtime/aggregate state, computes a proposal bounded by clock batch/catch-up settings, and proves the exact owner/fencing token again inside the authoritative serializable transaction. A stale worker cannot renew, release, complete a batch or advance. Duplicate/lost BullMQ wakes and multiple workers are harmless to authority; periodic PostgreSQL reconciliation finds due work independently.

A due gap no greater than `maxCatchUpTicks` is drained in `maxBatchTicks` transactions with yielding between batches. A larger continuous backlog produces no automatic command on repeated wakes. Recovery requires a deliberate pause/review, bounded manual advances as appropriate, then start to establish a fresh anchor; operators must not raise limits as an incident shortcut.

Transient execution failures receive bounded exponential retry. Exhaustion invokes a separate fenced `AutoPauseWorldClockV1`: the failed batch and sanitized `simulation_failures` row, `SimulationFailureRecordedV1`, `WorldClockAutoPausedV1`, and `error` clock mode commit together without skipping the action. Failure and batch rows prove each other bidirectionally: source tick must match the current clock/bounded batch range, attempts and completion time must agree, and an `EmitWorldNoticeV1` source must name the still-scheduled non-null action due at that exact tick. Clock representability exhaustion is represented by the narrow `WorldClockV1@1.0.0` failure source; its zero-width failed batch is allowed only for signed-integer boundary exhaustion under the guarded auto-pause command. Ordinary handler failures retain the due action. `ResolveSimulationFailureV1` supports `retry_after_repair` or `cancel_action`; both are append-only/audited, prove the implicit live clock transition from `error` to `paused`, clear the wall anchor, and never restart time automatically. Cancellation additionally proves the source action's state-aware terminal fact. Only `retry_after_repair` authorizes reuse of a failed batch after a compatible process repair; cancellation does not.

`@worldgraph/ledger` replays the entire ordered world stream into `SimulationReplayStateV1`, validates event hashes/positions, command grouping/ordinals/state revisions, simulation aggregate versions and transitions, schedules/notices and failure lifecycle, and treats non-simulation facts as ordered no-ops. It derives the seed only from the immutable active compiled artifact bound to honest genesis. `projection replay --projection simulation_runtime --target verify` stores audited replay identity and checksum only; compare refuses a changed source head, recomputes the checksum, proves JavaScript/PostgreSQL parity and reports a payload-free first divergent JSON pointer. `ledger verify` requires the simulation checkpoint at the runtime head and equal to the live checksum.

There is intentionally no automatic simulation repair swap. The M06 `ProjectionRepairAnchoredV1`/`repair-swap` function is graph-only and rejects a simulation run. Simulation divergence freezes writers and requires evidence preservation, owner-audited verification, restore/PITR or a separately reviewed append-only forward repair. Operators must not patch clock, schedule, checkpoint, event, ledger, batch or failure rows in place.

## Security, privacy, and operations state

- Manual commands retain authenticated session, explicit Origin, CSRF, active membership, capability, expected world/state/aggregate/tick versions, request-bound idempotency and bounded rate checks. Server-derived actor/correlation/causation metadata cannot be selected by clients.
- Worker authority is limited to the fixed `worldgraph:simulation-worker` principal and server-held lease owner/token. Both are proven inside the same transaction as state writes. Database grants keep schedule allocation, lease mutation, checkpoints and protected state transitions behind owner-defined functions/gates.
- Strict contracts and database constraints bound ticks, catch-up, schedules, priorities, payload bytes, text/control characters, returned events/schedules, attempts and transaction work. Current/past schedules, unknown versions, cross-world identifiers, forged system actors and forged fencing state fail closed.
- The pure package has no persistence, network, AI, provider, Redis, filesystem, locale, wall-time, environment or ambient-random authority. Future process versions require a new code-owned descriptor, schemas, privacy/history classification, golden outcome, migration/compatibility decision, failure/replay coverage and rollout plan.
- Notice visibility is `public`, `member` or `creator` and is applied before pagination. Notice text is bounded plain text and rendered as text. Queue messages contain only world ID, queue schema and expected fencing epoch. Logs, traces, metrics and failure context omit payload/notice text, raw errors, actor/session/IP material, hashes, lease owner/token and uncontrolled identifiers.
- `SIMULATION_CONTINUOUS_ENABLED=false` disables automatic advancement without deleting state or weakening manual commands. `SIMULATION_RECONCILIATION_INTERVAL_MS`, `SIMULATION_LEASE_MS`, `SIMULATION_MAXIMUM_WORLDS_PER_RUN`, `SIMULATION_MAXIMUM_ATTEMPTS`, `SIMULATION_RETRY_BASE_MS`, and `SIMULATION_MAXIMUM_BACKOFF_MS` are bounded and validated at startup. ## Architecture decisions and deviations

- ADRs 0001–0011 remain. ADR 0012 accepts the integer-tick clock, PostgreSQL-owned scheduler/lease/fencing, wake-only Redis, code-owned pure registry, semantic outcome/checkpoint boundary, bounded failure auto-pause and evidence-only simulation replay.
- M07 strengthens the inherited owner-opened command gate for every initialized-world writer and closes the reserved simulation namespace with literal command/event/row parity. This is a deliberate integrity hardening beyond type/schema validation: direct application-role DML or replay-shaped facts cannot launder clock, schedule, notice, batch or failure corruption into a current checkpoint.
- `packages/simulation-command` is a narrow worker adapter rather than routing a system lease through the public `WorldCommandBus`. It uses the same command/event/ledger/checkpoint transaction semantics but binds a fixed server actor and live fencing proof that public callers cannot express.
- Operational batch runs, leases, wall anchors and redacted failure execution context are preserved for diagnosis but excluded from semantic replay/checksum authority. This is required for equivalent batch groupings and worker timing to converge.
- The graph replay/repair path was not generalized into a simulation auto-swap. M07 provides verified reconstruction and comparison evidence, while restoration remains PITR or a separately reviewed forward procedure.
- Continuous catch-up larger than the configured maximum intentionally creates no command. Manual bounded acknowledgement plus a fresh start anchor is the compatible fail-closed behavior.
- Failure payload schema retains the property names `processType`/`processVersion`; `WorldClockV1@1.0.0` is admitted only as the deterministic clock-overflow source. Process-execution telemetry and the action registry remain notice-only.
- A zero-width failed batch is a narrow exception for the non-advanceable signed-64-bit clock boundary and is accepted only inside the matching fenced auto-pause transaction. Normal batches require a positive bounded range.
- World-time renderability is stricter than numeric multiplication alone: configuration proves tick 1 and each target tick can be serialized as canonical UTC in calendar years 0001–9999. Invalid manual values reject without domain/state/batch writes; invalid compiled initialization falls back to the complete documented defaults.
- Running UI updates use bounded polling, not WebSocket/realtime transport. This is an explicit M07 non-goal; the outbox carries minimal future-facing event references without granting client authority.
- The deferred clock-write assertion trigger executes with invoker rights. The application role therefore receives `EXECUTE` only on the pure, text-to-hash helper `worldgraph_initial_simulation_outcome_hash_v1(text)` needed to verify initialization; `PUBLIC` remains revoked and no broader owner authority is granted. The separate deferred activation initializer remains owner-controlled and `SECURITY DEFINER`.
- API command inserts omit the database-owned `command_records.status` column and rely on its guarded `received` default. Application code also does not lock database-owned aggregate or world-ledger head rows; the security-definer allocator owns and serializes those heads while the application retains locks only on mutable runtime, clock, action, failure, and checkpoint rows.
- Both API integration harnesses execute request-path transactions with real `worldgraph_app` credentials while an owner client is reserved for setup and assertions. This closes the earlier owner-credential blind spot without weakening production grants.

## Known risks and retained incomplete work

- M07 supplies only clock/scheduler infrastructure and the world-notice process. Resource production, population, businesses, markets, currency, taxes, elections, governance, environment, physics and AI actor decisions remain absent by design.
- Managed PostgreSQL PITR, immutable external checkpoints, privileged integrity scanning, the reconciliation exporter, collector translation, alert/dashboard installation, paging routes and completed restore drills remain deployment responsibilities; local Compose does not claim them.
- The API and ordinary worker retain the inherited shared application database role. Owner-grade migration/operations credentials are separate, but production should continue splitting API, compiler/history and simulation-worker privileges.
- Process-local HTTP throttling is not a horizontally shared edge limiter. Database idempotency, serialization, leases and constraints protect correctness but not aggregate abuse volume across replicas.
- Large offline catch-up requires deliberate manual recovery. M07 intentionally has no unbounded background drain, cron/time-zone engine or automatic limit escalation.
- Only `EmitWorldNoticeV1@1.0.0`, process registry 1 and one PRNG algorithm are supported. Every semantic process/algorithm change requires explicit versioning, golden fixtures, replay compatibility and a controlled rollout; an incompatible rollout can intentionally leave a world auto-paused until repair.
- Simulation replay does not reconstruct wall anchors, row versions, lease/batch operational state or a directly swappable row image. There is no simulation auto-heal; corruption recovery remains frozen-writer restore/PITR or reviewed forward repair.
